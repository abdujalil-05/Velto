# Runbook: восстановление legacy-строк без владельца (miniapp)

Статус: черновик для утверждения PO (P1, до пилота). Основание: `docs/parity/ADR-068-070-v09-vault-dispatch.md` §«Ownerless / foreign legacy rows».
Документ процедурный: кода/эндпоинтов не добавляет. Названия AuditLog-событий ниже — **предложение, не реализовано**.
**Процедура ни разу не проводилась и не проверена** (ни на стенде, ни на реальном устройстве).

## 1. Что это за строки
- Строки офлайн-очереди до v3: нет `userId`/`companyId`, зашифрованы общим ключом устройства.
- Приложение показывает нейтральный `ForeignLegacyGate` (без счётчика, id и содержимого) и блокирует создание новых документов.
- Приложение **никогда** не расшифровывает, не отправляет (push) и не присваивает (claim) такие строки. Logout/expiry/смена пользователя/revoke их не удаляют.
- Pre-fix сборки в пилоте не использовались — такие строки не ожидаются; runbook нужен на случай исключения.

## 2. Решения PO (обязательны)
1. Нет автоматической переатрибуции строк текущему пользователю.
2. Поле автора внутри непроверенного документа (`agentId`/`userId`/`createdBy`) — **не доказательство** владения (не аутентифицировано, подделываемо на общем устройстве).
3. Строки остаются изолированными: без автоматического push/decrypt, без доступа другого пользователя.
4. Восстановление — только при **независимом проверяемом доказательстве** владения **и** отдельной авторизации: письменное одобрение OWNER компании + второе лицо + подтверждение документа самим пользователем.
5. Каждый шаг документируется и попадает в AuditLog.
6. Владение не доказано → документ остаётся заблокированным. Отсутствие доказательства **никогда** не является основанием для восстановления.
7. Admin-bypass, расшифровывающий ownerless-данные, **сейчас не реализован и не реализуется**. Это будущая работа: отдельный ADR + проверка `security-auditor`.

## 3. Границы (scope)
- Один tenant. Компания устройства определяется **последней аутентифицированной сессией устройства** (серверные данные сессии/аудита), а не полями payload.
- Если компанию устройства нельзя установить по серверным данным — процедура останавливается, устройство остаётся заблокированным.
- Межтенантные действия запрещены; `systemPrisma` для этого не используется.

## 4. Что считается независимым доказательством (кандидаты, каждый требует утверждения PO)
| Кандидат | Условие |
|---|---|
| Заказ/оплата, о которых агент сообщил как «не дошедших», и их нет на сервере | Агент описывает документ (клиент, дата, сумма) **до** любого доступа к строкам |
| Корреляция устройство/время по серверным логам и AuditLog | Последняя сессия устройства принадлежит этому агенту в окне создания документа |
| Подтверждение со стороны клиента/кассы | Клиент или кассир подтверждает факт сделки/оплаты независимо от устройства |

**Не является доказательством:** поля автора в payload; утверждение «это моё устройство»; то, что пользователь сейчас залогинен на устройстве; содержимое самих строк; устное согласие без письменной фиксации; отсутствие возражений других сотрудников.

## 5. Порядок действий и роли
| # | Шаг | Роль | AuditLog (предлагается) |
|---|---|---|---|
| 1 | Зафиксировать обращение: устройство, агент, дата, симптом (`ForeignLegacyGate`) | Support | `legacy_ownerless.case_opened` |
| 2 | Установить компанию устройства по последней аутентифицированной сессии (сервер) | Support + инженер | `legacy_ownerless.tenant_scoped` |
| 3 | Изъять устройство из оборота: не передавать другому сотруднику до закрытия кейса | OWNER компании | `legacy_ownerless.device_held` |
| 4 | Собрать независимые доказательства (§4) без доступа к строкам | Support + бухгалтер/кассир | `legacy_ownerless.evidence_recorded` |
| 5 | Оценить доказательства; недостаточно → п. 9 | OWNER + второе лицо | `legacy_ownerless.evidence_reviewed` |
| 6 | Письменное одобрение OWNER + подпись второго лица | OWNER, второе лицо | `legacy_ownerless.recovery_approved` |
| 7 | Пользователь письменно подтверждает, что документ его | Агент | `legacy_ownerless.user_confirmed` |
| 8 | Восстановление: **сейчас только повторный ввод документа** агентом через штатный поток; строки не расшифровываются (bypass отсутствует, §2 п.7) | Агент | `legacy_ownerless.reentered` |
| 9 | Не доказано → кейс закрыт со статусом «заблокировано», строки сохраняются | OWNER | `legacy_ownerless.case_closed_locked` |

Каждый шаг фиксирует: кто, когда, основание, ссылки на доказательства. Второе лицо ≠ OWNER и ≠ агент-заявитель.

## 6. Хранение, пока строки заблокированы
- Оставить на устройстве как есть (без изменений, без расшифровки).
- Устройство не перевыдаётся другому сотруднику до закрытия кейса.
- Опционально: зашифрованный экспорт на уровне устройства — **только по будущему ADR** (сейчас не реализован и не разрешён).

## 7. Бизнес-сверка возможных потерь
- Потерянные заказы/оплаты выявляются **серверными средствами**: сверка с клиентом (акт сверки, дебиторка), сверка кассы/кассовых смен, а не чтением строк.
- Найденные расхождения оформляются штатными документами (повторный ввод, корректировка) с обычным аудитом.

## 8. Утилизация строк
- Срок хранения: в `docs/release/FILE-RETENTION-MATRIX.md` строка «Offline device data» — «Device-side; no server policy», владелец PO → **срок — решение PO/юриста**.
- Удаление только: после истечения этого срока **и** письменного разрешения OWNER **и** завершения бизнес-сверки (§7).
- Запись в AuditLog: `legacy_ownerless.disposed` (кто разрешил, кто выполнил, устройство, дата).
- Механизм удаления на устройстве сейчас не реализован в приложении (logout/revoke строки не удаляют) — выбор механизма — отдельное решение.

## 9. Открытые вопросы для PO
- Утвердить список доказательств §4 (каждый пункт отдельно).
- Утвердить срок хранения (§8) с юристом.
- Реализация AuditLog-событий §5 и любого bypass/экспорта — отдельные ADR + `security-auditor`.
