# Пакет приёмки для бухгалтера пилота (1С)

> 2026-11-01. Основной документ: `docs/parity/1C-ACCOUNTANT-ACCEPTANCE.md` (поля mapping v2, вопросы для v3, сверка, ACK). Это сопроводительный лист: что подтвердить и в каком порядке.
> Подписывает **только бухгалтер клиента** (строка Accounting в `docs/release/SIGNOFF-v0.9.md`). Разработчики и агенты не подписывают и не заполняют ответы за бухгалтера.

## Текущие ограничения (сообщить бухгалтеру до начала)

- Экспорт CSV/XML работает по **mapping v2**. Документ с НДС ≠ 0, скидкой, упаковкой (не базовой единицей) или расхождением сумм **отклоняется целиком** (`1C_EXPORT_UNSUPPORTED_COMBINATION`), файл не создаётся. Это защита, а не ошибка.
- Для плательщиков НДС большинство документов сейчас **не выгружаются**. Mapping v3 будет сделан **только** после получения реальных образцов и письменных ответов ниже. По догадкам не реализуется.
- Velto не загружает данные из 1С. Защита от дублей при повторной загрузке в 1С возможна только если 1С ищет документ по `Ид` (UUID Velto).
- Excel-выгрузка служит **информационным реестром**. Она не подтверждает интеграцию и не принимает ACK (409).

## Что нужно подтвердить

| # | Вопрос | Раздел основного документа | Ответ бухгалтера | Доказательство |
|---|---|---|---|---|
| 1 | Конфигурация 1С (например, «Бухгалтерия», «УТ»), редакция и версия платформы | §1 | | скриншот «О программе» |
| 2 | Ставки НДС, цена с НДС или без, НДС сверху или в том числе, построчно или по документу | §5 | | письменно + образец документа |
| 3 | HALF_UP до 2 знаков построчно на **реальных** документах (пример 3,333 × 1,50 = 5,00) | §7 | | сверка 5–10 документов |
| 4 | Как передавать скидку: процент, сумма или цена со скидкой | §4 | | образец |
| 5 | Единица измерения: базовая или упаковка, коды ОКЕИ | §6 | | образец |
| 6 | Mapping v3: контрагент (код / ИНН / наименование), номенклатура, валюта, хозоперация, склад, организация, договор | §3 | | утверждённая таблица полей |
| 7 | Идентификатор документа: куда 1С кладёт `Ид`, ищет ли по нему при загрузке | §8 | | скриншот реквизита |
| 8 | Повторная загрузка того же файла не создаёт дублей | §8 | | два импорта, количество документов в 1С |
| 9 | Сумма строк = итог документа, допуск 0,00 | §7 | | таблица сверки |

## Порядок работы

1. Встреча 1 (вопросы 1, 2, 4, 5, 6, 7): бухгалтер передаёт 5–10 реальных обезличенных документов из своей 1С.
2. Разработка: решение PO по mapping v3 → ADR → реализация и тесты. До этого шага v2 остаётся ограниченным.
3. Встреча 2 (вопросы 3, 8, 9): выгрузка с тестового стенда → загрузка в **тестовую копию** базы 1С клиента → сверка → ACK ACCEPTED/REJECTED в Velto.
4. Подпись чек-листа §10 основного документа и строки Accounting.

## Что не принимается как доказательство

- Зелёный CI, unit-тесты, успешная Excel-выгрузка, сверка на демо-данных Velto без загрузки в 1С клиента.
